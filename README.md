# MAKEZERO

숫자를 이어서 **10**을 만드는 나무블록 퍼즐. 웹(TypeScript)으로 만들고 Capacitor로 감싸서 Google Play에 올립니다.

## 모드

| 모드 | 목표 | 자원 |
| --- | --- | --- |
| **스토리** | 남은 타일을 목표 이하로 줄여 별 획득 | 스테이지마다 정해진 섞기 횟수 |
| **타임어택** | 60초 동안 최대 점수 | 없음, 대신 자동 보충 |
| **무제한** | 끝까지 지우기 | 섞기 5회 · 힌트 3회 |

**스토리** — 전 20 스테이지, 5개씩 4챕터. 보드는 5×8(40칸)에서 10×15(150칸)까지 커지고, 별을 받는 기준은 점점 빡빡해집니다. 챕터의 마지막 스테이지를 깨면 캐릭터가 나오는 스토리 장면이 재생됩니다.

## 규칙

보드는 처음 딜된 크기 그대로이며 **절대 커지지 않습니다.** 타일은 화면에 맞춰 자동으로 크기가 정해져 스크롤이 없습니다.

**지울 수 있는 조합** — 이어붙인 타일의 합이 **정확히 10**이면 지워집니다. 2개부터 5개까지.

```
4+6    3+7    1+2+7    1+1+8    1+2+3+4    1+2+3+2+2
```

같은 숫자끼리 지우는 규칙은 **없습니다.** 3+3은 6이라 지워지지 않습니다. 다만 `1+1+8`처럼 체인 안에 같은 숫자가 들어가는 건 됩니다.

**연결 — 직선 시야**

> 가로·세로·대각선으로 **직선**을 그었을 때, 사이에 **살아있는 숫자가 하나도 없으면** 이어집니다.

붙어 있으면 당연히 이어지고, 지워진 칸은 **몇 칸이든 통과**합니다. 보드가 비어갈수록 사거리가 늘어납니다. 3개 이상은 고른 순서대로 한 칸씩 이어지면 되고, 전부가 서로 붙어 있을 필요는 없습니다.

**점수** — 2개 10점 · 3개 30점 · 4개 70점 · 5개 150점. 개수로만 결정됩니다. 같은 타일이라도 `1+1`(10점)보다 `1+8+1`(30점)이 낫기 때문에, 어떤 순서로 잇느냐가 실력입니다.

**조작** — 타일을 하나씩 **탭**하거나 손가락으로 **드래그**해서 잇습니다. 드래그는 뗄 때, 탭은 합이 10이 되는 순간 확정됩니다.

**섞기** — 막혔을 때 남은 숫자의 **자리만 바꿉니다.** 숫자가 늘지도 줄지도 않아 보드 크기가 유지됩니다.

**별** — 남은 타일 수로 채점합니다. 목표는 스테이지마다 화면에 표시됩니다.

### 보드가 만들어지는 방식

보드는 랜덤 숫자를 뿌리는 게 아니라 **합이 10인 조각들을 이어붙여** 만듭니다.

이유가 있습니다. 조합 하나가 정확히 10씩 지우므로, 남은 숫자 총합을 10으로 나눈 **나머지가 절대 변하지 않습니다.** 랜덤으로 뿌리면 그 나머지가 0이 아닐 확률이 90%고, 그러면 아무리 잘해도 보드를 다 지울 수 없습니다. 실제로 시뮬레이션했을 때 랜덤 보드는 120판 전부 실패했습니다.

조각으로 구성하면 총합이 항상 10의 배수라 완전 클리어가 가능해집니다. 다만 숫자가 맞아떨어져도 **자리가 맞아떨어질지는 딜 나름**이라, 별 3개도 완전 클리어가 아니라 작은 숫자 목표로 잡았습니다.

## 구조

```
src/game/     순수 게임 로직 (DOM 의존 없음, 테스트 대상)
  board.ts      보드 표현, 연결 판정, 줄 정리, ＋ 동작
  rules.ts      조합 성립 판정과 점수
  hint.ts       가능한 조합 탐색 (힌트 · 교착 감지)
  game.ts       모드별 상태 전이 (승패, 타이머, 별 채점)
  story.ts      챕터 · 대사 · 스테이지 난이도 곡선 · 별 기준
src/ui/
  app.ts        화면 전환과 HUD
  boardView.ts  타일 렌더링과 드래그 선택
  storage.ts    진행 상황 저장
public/story/ 캐릭터 이미지
android/      Capacitor가 생성한 네이티브 프로젝트
store/        Play 스토어 등록용 이미지
```

게임 규칙은 전부 순수 함수라 UI 없이 테스트됩니다. `solver.test.ts` 는 그리디 봇으로 20개 스테이지를 전부 시뮬레이션해서 **통과할 수 없는 스테이지가 없는지**, 그리고 난이도가 실제로 우상향하는지 검사합니다. 난이도 숫자를 바꾸면 이 테스트가 먼저 알려줍니다.

```bash
npm install
npm run dev        # 개발 서버
npm test           # 규칙 테스트
npm run typecheck
npm run build      # dist/ 생성
```

## 캐릭터와 스토리 교체

`src/game/story.ts` 의 `CHAPTERS` 배열 하나만 고치면 됩니다.

```ts
{
  id: "sprout",
  title: "1장 · 첫 그루터기",
  character: "./story/sprout.svg",   // public/story/ 아래 경로
  characterName: "새싹",
  lines: ["첫 번째 대사", "두 번째 대사"],
}
```

- **이미지** — `public/story/` 에 같은 파일 이름으로 덮어쓰면 코드는 건드릴 필요가 없습니다. 지금 들어있는 SVG는 **자리를 잡아둔 임시 그림**입니다. png · webp · jpg 도 되고, 세로가 조금 긴 비율(대략 128×160)에 맞춰 그리면 잘 들어맞습니다.
- **대사** — `lines` 배열에 넣는 만큼 한 줄씩 넘어갑니다. 개수 제한 없습니다.
- **챕터 수** — 배열에 항목을 추가하면 스테이지 수도 같이 늘어납니다(챕터당 5스테이지). 난이도 곡선은 전체 스테이지 수에 맞춰 자동으로 다시 펴집니다.

## 난이도 조정

`src/game/story.ts` 상단의 두 줄이 전부입니다.

```ts
const EASIEST = { width: 5, rows: 8, shuffles: 5, stars: [0.32, 0.18, 0.08] };
const HARDEST = { width: 10, rows: 15, shuffles: 1, stars: [0.26, 0.14, 0.05] };
```

첫 스테이지와 마지막 스테이지의 값만 정하면 중간은 선형 보간됩니다. `stars` 는 남아도 되는 타일의 **비율**입니다.

숫자 배분(`EASY_GROUPS` / `HARD_GROUPS`)은 직관과 반대로 동작하니 주의하세요. **큰 조각(5개짜리)을 많이 딜하면 쉬워집니다.** 5개 합이 10이면 한 타일당 평균 2라 보드가 작고 유연한 숫자로 차거든요. 반대로 **2개짜리 짝을 많이 딜하면 어려워집니다** — 숫자가 넓게 퍼져서 1이나 2를 정확히 필요로 하는 8·9가 고립됩니다. 시뮬레이션 결과 같은 스테이지에서 남은 타일이 9.8개 대 34.2개로 갈렸습니다.

바꾼 뒤 `npm test` 를 돌리면 그리디 봇이 새 곡선으로 20 스테이지를 다시 시뮬레이션합니다.

## Android 빌드

### 1. 업로드 키 만들기 (최초 1회)

이 키를 잃어버리면 **같은 앱을 다시 업데이트할 수 없습니다.** 안전한 곳에 백업하세요.

```bash
keytool -genkeypair -v -keystore android/upload-keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

`android/keystore.properties` 를 만듭니다 (이 파일과 `.jks` 는 `.gitignore` 로 커밋되지 않습니다):

```properties
storeFile=upload-keystore.jks
storePassword=<위에서 입력한 비밀번호>
keyAlias=upload
keyPassword=<위에서 입력한 비밀번호>
```

### 2. AAB 만들기

로컬에 Android SDK(Android Studio 또는 command line tools)가 있으면:

```bash
npm run android:bundle
# → android/app/build/outputs/bundle/release/app-release.aab
```

SDK를 설치하고 싶지 않다면 GitHub Actions 의 **Release AAB** 워크플로를 수동 실행하면 됩니다. 아래 4개 시크릿을 저장소에 등록해두세요.

| 시크릿 | 값 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 android/upload-keystore.jks` 결과 |
| `ANDROID_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | 키 비밀번호 |

빌드된 `.aab` 는 워크플로 실행 결과의 아티팩트로 내려받습니다.

### 버전 올리기

`android/app/build.gradle` 의 `versionCode`(업로드마다 반드시 증가) 와 `versionName` 을 수정합니다.

### 알아둘 것

- **Target API** — 2026-08-31부터 신규 앱은 Android 16(API 36) 이상이어야 합니다. 이 프로젝트는 `android/variables.gradle` 에서 이미 36으로 설정되어 있습니다.
- **applicationId** — `io.github.junyyyong.makezero`. 스토어에 한 번 올리면 **영구히 변경 불가**하므로, 다른 값을 쓰려면 첫 업로드 전에 `capacitor.config.ts`, `android/app/build.gradle`, `android/app/src/main/AndroidManifest.xml`, `MainActivity.java` 의 패키지 경로를 함께 바꾸세요.
- **INTERNET 권한** — 게임은 완전히 오프라인이지만 Capacitor 템플릿의 기본 권한이 남아 있습니다. 실기기에서 정상 동작을 확인한 뒤 `AndroidManifest.xml` 에서 제거하면 Data Safety 양식이 더 단순해집니다.
- **광고 없음** — AdMob SDK를 넣지 않았습니다. 나중에 붙이면 개인정보처리방침과 Data Safety 양식을 함께 갱신해야 합니다.
