## 0. 작성 규칙

- **시간은 KST(UTC+9)** 로 적습니다. 컨테이너는 UTC라서 `date -u` 결과에 9시간을 더하면 됩니다.
- 형식: `## YYYY-MM-DD` 아래에 `### HH:MM · 한 줄 제목 · [도구]` 를 시간순으로 쌓습니다.
- 한 항목에 **무엇을 / 왜 / 어디를** 세 가지를 적습니다. 특히 **왜**를 빼먹지 마세요.
  시뮬레이션이나 측정으로 정한 값이면 **숫자를 같이** 남깁니다.
- 결정이 뒤집히면 **이전 항목을 지우지 말고** 새 항목에 "무엇을 뒤집었는지" 적습니다.
  이 프로젝트는 직관과 반대되는 결론이 많아서, 되돌린 이유가 기록에 남아야 또 되돌아가지 않습니다.
- 자세한 근거는 `docs/DECISIONS.md`(왜), `docs/BALANCE.md`(수치), `docs/RULES.md`(규칙),
  `docs/ARCHITECTURE.md`(구조), `docs/CONTENT.md`(에셋)로 나눠 적고, 여기서는 **링크만** 겁니다.

### 손대기 전에 알아야 할 것

1. `src/core/` 는 **DOM을 모릅니다.** 규칙은 전부 순수 함수라 브라우저 없이 테스트됩니다.
   의존 방향은 `ui → content → core` 한 방향입니다. 거꾸로 import 하지 마세요.
2. 규칙을 판정하는 곳은 **`src/core/rules.ts` 하나뿐**입니다. 조합 판정을 바꾸려면 여기만 고칩니다.
3. 밸런스 숫자는 **`src/content/stages.ts` 맨 위 두 줄**(EASIEST / HARDEST)이 전부입니다.
   중간 스테이지는 보간됩니다.
4. 스킨은 **`src/ui/styles/tokens.css`** 에서 시작합니다. 팔레트 값이 전부 여기 있습니다.
5. 바꾸고 나면:
   ```bash
   npm test          # 규칙 · 밸런스 · 튜토리얼 (81개)
   npm run build     # 타입 검사 + 번들
   npm run preview   # 그리고 다른 터미널에서
   CHROME_PATH=/opt/pw-browsers/chromium npm run test:layout   # 실제 브라우저 레이아웃
   ```
   레이아웃 깨짐은 **유닛 테스트로 절대 못 잡습니다.** 스킨을 건드렸으면 `test:layout` 을 꼭 돌리세요.

### 17:50 · 스토리를 99 스테이지로, 목표는 "전부 지우기" · [Claude]

네 가지입니다.

1. **5칸을 골랐는데 10이 아니면 즉시 거절.** 여섯 번째가 없으니 그 선택은 이미 죽었는데
   화면에는 살아 있었습니다. 보드가 흔들리고 그 다섯 칸이 **빨갛게 번쩍인 뒤** 놓입니다.
   번쩍임이 핵심 — 그냥 사라지면 "안 눌린 건가"와 구분이 안 됩니다.
   → [DECISIONS 15](./DECISIONS.md)

2. **스토리 목표 = 판을 전부 지우기.** 완전 탐색으로 확인했습니다 — **모든 스테이지, 모든
   시드에서 판은 100% 전부 지울 수 있습니다.** 그런데 조각을 가로질러 지우면 짝 잃은
   타일이 남습니다. 봇 측정: 아무렇게나 두면 초반 35% → 후반 **0%**, 항상 긴 조합만
   집으면 거의 0%, **판을 계속 다 지울 수 있게 유지하는 수만 고르면 100%.**
   즉 **막히는 건 운이 아니라 실수**입니다. → [DECISIONS 14](./DECISIONS.md)

3. **한 수 물리기(undo) 추가.** 편의 기능이 아니라 위 목표를 공정하게 만드는 자원입니다.
   **판이 죽은 뒤에도 쓸 수 있고**, 그때 결과창이 "한 수 물리기"를 먼저 권합니다.
   마지막 스테이지에도 1회는 남겨둡니다 — 0이면 막힌 판을 살릴 방법이 사라집니다.

   별도 바뀌었습니다: ★★★ = 전부 지움 + 도움 0회 / ★★ = 전부 지움 / ★ = 조금 남김(진행은 됨).

4. **99 스테이지.** 11챕터 × 9. 보드 4줄→11줄, 배분 큰조각→짝위주, 힌트 5→0, 물리기 5→1.
   난이도 다이얼은 크기가 아니라 **실수의 대가**입니다. 스테이지별 측정치는 [BALANCE](./BALANCE.md).

**새 테스트** — `content/clearable.test.ts`. 모든 스테이지의 판이 정말 전부 지워지는지
완전 탐색으로 검사하고, 신중한 봇이 실제로 끝까지 비우는지도 확인합니다.
스토리의 전제가 깨지면 여기서 먼저 걸립니다.

**주의** — 챕터 11개가 캐릭터 그림 4장을 돌려 씁니다. 그림이 준비되면 `chapters.ts` 의

### 20:48 · 그림 수집 게임으로 · 숫자 비율 · 나누기 아이템 · [Claude]

구조를 바꿨습니다. 네 가지입니다.

1. **숫자 비율.** "4~5개 조합을 만들면 1과 2가 다 없어진다"가 측정으로 확인됐습니다 —
   1스테이지 판의 **1이 37%, 2가 18%로 전체의 55%**, 9는 1%였습니다. 원인은 딜러가
   그룹 크기만 정하고 숫자는 균등난수로 굴린 것. 이제 **합이 10인 그룹 목록에서
   "지금 판이 모자란 숫자"를 보고 고릅니다.** 1이 37%→23%, 9가 1%→8%.
   덤으로 이 비율이 그룹 크기까지 정해서 다이얼이 하나로 줄었습니다.
   → [DECISIONS 16](./DECISIONS.md)

2. **그림 드러내기.** 판 뒤에 그 스테이지의 그림이 깔리고, 지운 칸이 투명해지며
   그림이 드러납니다. 전부 지우면 **그림을 얻어 갤러리에 모읍니다.**
   따라오는 제약이 하나 — **스토리는 줄이 무너지면 안 됩니다**(`keepBoard`).
   한 줄이 비었다고 위가 내려앉으면 드러난 구멍이 그림과 어긋납니다.
   → [DECISIONS 17](./DECISIONS.md)

3. **별 등급 삭제.** 목표가 이분법이 됐으니(얻거나 못 얻거나) 별을 얹으면 상이 두 개가
   되어 흐려집니다. `내 기록` 화면은 **갤러리**가 됐습니다.

4. **나누기 아이템.** 블록 하나를 합이 같은 조각으로 쪼갭니다(5 → 3+2 또는 1+1+1+2).
   어떻게 쪼개질지는 못 고릅니다. **함정이 하나 있었습니다** — 한 수로 지울 수 있는 건
   5칸까지라, 4칸 그룹 안의 블록을 셋으로 쪼개면 6칸이 되어 못 지웁니다. 그래서
   **쪼갤 때마다 `canEmpty` 로 검사하고 판을 망치는 쪼개기는 다시 굴립니다.**
   → [DECISIONS 18](./DECISIONS.md)
