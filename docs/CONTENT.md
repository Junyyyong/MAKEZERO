# 로고

그림 두 장이 따로 있습니다.

| 파일 | 나오는 곳 |
| --- | --- |
| `public/cover.webp` | 앱을 켜면 나오는 **표지**. 화면을 꽉 채웁니다 |
| `public/cover-logo.svg` | **타이틀 화면**의 워드마크 |

## 표지 (`cover.webp`)

화면 전체를 `cover` 로 채웁니다 — 폰 비율에 맞춰 **가장자리가 잘립니다.** 그러니 중요한 건 가운데에 두세요. 세로로 긴 폰 비율(9:20 안팎)에 맞춰 그리면 잘리는 게 가장 적습니다.

원본은 얼마든지 커도 됩니다. 넣을 때 **가로 1080px WebP** 로 줄여서 씁니다(지금 250KB). 표지 안에 로고가 이미 들어 있으므로 그 위에 아무것도 그리지 않습니다.

## 워드마크 (`cover-logo.svg`)

SVG(벡터)라 크기를 아무리 키워도 안 깨지고, 화면 배율도 신경 쓸 필요가 없습니다.

- **여백 없이 글자 가장자리에 딱 맞게** 잘라 주세요. 여백이 들어 있으면 화면에서 로고가 실제보다 작아 보이고 가운데도 어긋납니다
- **배경은 투명**하게. 밤하늘 위에 얹히는 그림입니다
- 크기는 CSS 가 정합니다(`title.css` 의 `.brand-mark`). 지금 그림은 **세로가 더 긴** 비율이라 폭을 190px 로 잡았습니다. 가로로 긴 그림으로 바꾸면 이 값도 같이 키워야 합니다

**팔레트는 아직 예전 로고 기준입니다.** `tokens.css` 의 시안·마젠타는 블록 워드마크에서 뽑은 색인데, 지금 로고는 주황·노랑 계열입니다. 스킨 전체를 새 로고에 맞추는 건 아직 안 했습니다.

# 그림 (갤러리)

스테이지마다 그림이 한 장 있고, 판을 전부 지우면 그 그림을 얻습니다. 목록은 `src/content/gallery.ts` 의 `PLATES` 입니다.

```ts
{ stage: 1, title: "새싹 1", art: "./gallery/001.webp" }
```

- `art` 는 `public/` 아래 경로입니다. **비워 두면 스테이지 번호로 만든 임시 그림**이 대신 나옵니다
- 정사각형이 가장 잘 맞습니다. 판이 세로로 길어져도 `cover` 로 잘리며 채워집니다
- 그림은 판 **뒤**에 깔리고 지운 칸으로 보입니다. 그러니 **가장자리보다 가운데가 중요한 구도**가 좋습니다
- 갤러리 목록에서는 작은 정사각형으로, 눌러서 볼 때는 크게 나옵니다
- 판 위에서는 **블록 모양으로 나뉘어** 드러나고, 갤러리에는 나뉘지 않은 원본이 들어갑니다

### 그림이 나오는 자리 셋

같은 `art` 가 세 군데에 쓰입니다. 하나만 준비하면 됩니다.

- **게임판 뒤** — 블록을 지운 만큼, 블록 모양으로 나뉘어 드러납니다
- **스테이지 카드** — 스테이지를 고르면 뜨는 카드. 아직 못 얻은 스테이지는 `?` 만 보입니다
- **갤러리** — 나뉘지 않은 원본

### 99장을 한 번에 넣으려면

`public/gallery/001.webp` … `099.webp` 로 넣고 `PLATES` 의 `art` 를 채우면 됩니다. 파일명 규칙만 지키면 한 줄로 생성할 수 있습니다.

```ts
art: `./gallery/${String(stage).padStart(3, "0")}.webp`
```

# 캐릭터와 스토리 교체

## 대사

`src/content/chapters.ts` 의 `CHAPTERS` 배열만 고치면 됩니다.

```ts
{
  id: "sprout",                    // 저장용 식별자 — 바꾸면 그 챕터를 다시 봅니다
  title: "1장",                    // 챕터 선택 화면과 스토리 연출에 그대로 나옵니다
  character: "./story/sprout.svg", // public/ 아래 경로
  characterName: "새싹",
  lines: ["첫 번째 대사", "두 번째 대사"],
}
```

`lines` 에 넣은 만큼 한 줄씩 넘어갑니다. 개수 제한 없습니다.

`title` 은 지금 **`1장` … `11장` 번호뿐**입니다. 예전엔 `1장 · 첫 그루터기` 처럼 소제목이 붙어 있었는데, 챕터 선택 화면에서 이름이 길면 오른쪽 진행 숫자를 밀어냈고 무엇보다 **아직 정해지지 않은 이야기의 이름**이었습니다. 이야기가 정해지면 여기에 다시 붙이면 됩니다 — 화면 쪽은 `title` 을 그대로 찍기만 하므로 고칠 곳이 없습니다.

## 이미지

`public/story/` 에 **같은 파일 이름으로 덮어쓰면** 코드는 건드릴 필요가 없습니다.

지금 들어있는 SVG 4개는 **자리를 잡아둔 임시 그림**이고, 11개 챕터가 그 4장을 돌려 씁니다. 챕터마다 다른 그림을 주려면 `public/story/` 에 파일을 추가하고 `chapters.ts` 의 `character` 경로만 바꾸면 됩니다. 조건은 이렇습니다.

- 형식: svg · png · webp · jpg
- 비율: 세로가 조금 긴 형태 (기준 128×160)
- 화면에서 148px 정도로 표시됩니다
- 배경은 투명하게 두면 카드 위에 자연스럽게 얹힙니다

다른 이름을 쓰고 싶으면 `chapters.ts` 의 `character` 경로도 같이 바꾸세요.

## 챕터 추가

`CHAPTERS` 에 항목을 추가하면 **스테이지 수도 같이 늘어납니다** (챕터당 9스테이지, 지금은 11챕터 99스테이지). 난이도 곡선은 전체 스테이지 수에 맞춰 자동으로 다시 펴집니다.

챕터당 스테이지 수를 바꾸려면 같은 파일의 `STAGES_PER_CHAPTER` 를 고칩니다.

## 스토리가 나오는 시점

챕터의 **마지막 스테이지를 별 1개 이상으로 통과**했을 때 한 번 재생됩니다. 이미 본 챕터는 `seenChapters` 에 기록되어 다시 나오지 않습니다.

테스트 중에 다시 보려면 브라우저 콘솔에서:

```js
localStorage.removeItem("makezero.progress.v1");
```

# 화면 흐름

```
타이틀 ─ 스토리 ──→ 챕터 목록 ─→ 스테이지 그리드 ─→ 스테이지 카드 ─→ 게임
       ├ 타임어택 ─→ 시작 화면 ────────────────────────────────→ 게임
       └ 무제한 ──→ 시작 화면 ────────────────────────────────→ 게임
```

- 모드를 눌러도 바로 시작하지 않습니다. 스토리는 어떤 그림이 걸려 있는지 보고 고르고, 시간 모드는 무엇을 재는지 먼저 보여줍니다
- 게임 안의 뒤로가기는 **들어온 길로** 나갑니다. 스토리는 스테이지 그리드로, 시간 모드는 타이틀로
- 결과 패널의 "다시 하기"는 고르는 화면을 거치지 않고 그 자리에서 다시 시작합니다
- 화면 사이 전환은 `AppStateMachine` 이 지킵니다. 허용되지 않은 이동은 예외로 막힙니다 (`src/ui/appStateMachine.ts`)

# 튜토리얼

`src/content/tutorial.ts` 의 `TUTORIAL_STEPS` 배열입니다. 다섯 단계로, **직접 눌러봐야 넘어갑니다.**

```ts
{
  id: "sum-ten",
  layout: [            // 0 은 빈 칸
    [4, 0, 6],
    [0, 3, 0],
    [2, 0, 0],
  ],
  instruction: "숫자를 눌러 합이 10을 만들면 지워집니다.\n4와 6을 눌러보세요.",
  reward: "그거예요! 합이 10이면 사라집니다.",
}
```

## 보드를 고칠 때 꼭 지킬 것

**보드마다 합이 10이 되는 조합이 정확히 하나만 있어야 합니다.**

그래야 게임의 진짜 규칙으로 정답을 판정할 수 있습니다. "이게 내가 의도한 수인가?"를 따로 검사하지 않으니, 튜토리얼이 규칙과 어긋날 일이 없습니다.

정답 외의 타일은 있어도 됩니다. 오히려 그게 교육 포인트입니다.
- `same-number` 단계의 3 두 개 — 짝처럼 보이지만 안 지워짐
- `anywhere` 단계의 4들 — 9와 1 사이가 멀다는 걸 보여줌

**레이아웃을 바꾸면 `npm test` 를 돌리세요.** `content/tutorial.test.ts` 가 정답이 두 개 이상 생겼는지 검사합니다.

## 언제 나오나

**처음 실행하면 자동으로** 나옵니다. 끝내거나 건너뛰면 다시 안 나오고, 타이틀 화면의 "튜토리얼"로 언제든 다시 볼 수 있습니다.

다시 테스트하려면 브라우저 콘솔에서:

```js
localStorage.removeItem("makezero.progress.v1");
```

# 판이 끝날 때 나오는 연출

판이 끝나면 화면이 50% 검게 깔리고 **두 박자**로 끝납니다.

1. **`TIME OUT` / `BOARD FULL` 과 큰 점수** — 4초
2. **점수에 따른 글씨와 춤추는 영상**
영상이 끝나면 **마지막 장면에서 멈추고 `TAP TO CONTINUE`** 가 뜹니다. 화면을 누르면 결과창으로
넘어갑니다 — 시간이 아니라 **플레이어가 끝냅니다.**

재생 중에는 탭이 통하지 않습니다. 손가락이 스쳐서 연출을 건너뛰는 일이 없도록요.

**글씨 · 영상 · 안내문은 자리가 고정입니다.** 셋 다 처음부터 자기 자리를 차지하고 있다가
보이기만 하므로, 영상이 뜨거나 안내문이 나타난다고 나머지가 밀리지 않습니다. 영상 칸은
**화면 높이의 46%** 로 고정이라 비율이 다른 영상으로 바꿔도 자리가 그대로입니다.

| 점수 | 글씨 |
| --- | --- |
| 500 이상 | `AMAZING!` |
| 200 이상 | `GREAT!` |
| 50 이상 | `NICE!` |
| 그 미만 | `GOOD TRY!` |

## 영상 넣는 법

파일 두 개를 한 쌍으로 `public/movie/` 에 두고, `src/ui/screens/cheer.ts` 맨 위 목록에
줄을 더합니다.

```ts
const CHEER_CLIPS: readonly Clip[] = [
  { video: "./movie/3.webm", sound: "./movie/3.mp3" },
  { video: "./movie/4.webm", sound: "./movie/4.mp3" },
  // …
];
```

**매번 하나를 무작위로 골라 재생합니다.** 목록이 비면 글씨만 1.4초 나오고 넘어가므로,
영상이 없어도 게임은 멀쩡합니다.

**그림과 소리를 왜 따로 두나** — 소리가 들어 있는 영상은 브라우저가 자동재생을 거부할 수
있습니다. 그림은 음소거로 두고 소리를 옆에서 같이 틀면 그 제한을 안 받습니다. 두 파일은
**길이가 같아야** 하고, 같은 순간에 시작합니다. 소리는 설정의 **효과음 스위치**를 따릅니다 —
꺼 두면 그림만 나옵니다. `sound` 는 없어도 됩니다.

**소리가 나려면 먼저 한 번 만져야 합니다** — 아이폰은 타이머에서 시작하는 `<audio>` 를
막습니다. 그래서 **첫 터치 때 4밀리초짜리 무음 파일을 한 번 재생해 둡니다**(`Cheer.unlock`).
그 뒤로는 이 요소가 계속 허락된 상태라, 4초 뒤 타이머에서 트는 노래도 나옵니다.

**단, 아이폰 옆면의 무음 스위치는 코드로 못 이깁니다.** 무음으로 해 두면 `<audio>` 와
`<video>` 소리는 무조건 안 납니다. 그걸 무시하려면 네이티브 쪽에서 오디오 세션을
`playback` 으로 잡아야 하고, 그건 Capacitor 껍데기의 몫입니다.

## 어떤 형식으로 주면 되나

**그림은 WebM (VP9 + 알파), 소리는 MP3.** 안드로이드에서 투명 배경이 그대로 나옵니다.

| 형식 | 투명 | 안드로이드 | 아이폰 사파리 |
| --- | --- | --- | --- |
| **WebM (VP9 + alpha)** | 완전 | ✅ | ❌ |
| MOV/MP4 (HEVC + alpha) | 완전 | ❌ | ✅ |
| MP4 (H.264) | **없음** | ✅ | ✅ |

**투명 영상은 양쪽에서 다 되는 형식이 없습니다.** 지금 목표가 구글 플레이(안드로이드)이므로
WebM 하나면 충분합니다.

**아이폰에서 배경이 까맣게 보인다면 그게 원인입니다.** 파일이 잘못된 게 아니라 iOS 사파리가
VP9 알파를 못 읽습니다. 아이폰에서도 투명하게 하려면 **같은 영상을 HEVC 알파로도** 뽑아
`<source>` 두 줄로 넣어야 합니다.

```bash
ffmpeg -i dance.mov -c:v hevc_videotoolbox -alpha_quality 0.9 -tag:v hvc1 -an movie/4.mov
```

내보낼 때 `ffmpeg` 예시입니다.

```bash
ffmpeg -i dance.mov -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 0 -crf 32 -an movie/4.webm
ffmpeg -i dance.mov -vn -c:a libmp3lame -q:a 4 movie/4.mp3
```

`-pix_fmt yuva420p` 가 알파를 살리는 부분, `-an` 이 그림에서 소리를 빼는 부분입니다.

## 만들 때 지킬 것

- **그림은 소리 없이**(`-an`), 소리는 **같은 길이의 MP3** 로 따로
- **1~3초 권장.** 다 재생돼야 탭이 열립니다. 지금 `3.webm` 은 4.7초입니다
- **루프 없이 한 번.** 끝나는 순간이 곧 다음 화면입니다
- **가로 700px 안팎.** 화면에서 최대 420px, 세로는 화면의 48% 까지 나옵니다.
  글씨는 영상 **위쪽**에 따로 놓이므로 겹치지 않습니다
- 배경 **투명**. 글씨가 영상 위에 겹칩니다

**크로마키(초록 배경)는 권하지 않습니다.** 브라우저에서 지우려면 매 프레임을 캔버스로
처리해야 하는데, 느리고 캐릭터 가장자리에 초록 테두리가 남습니다.

영상이 8초 안에 안 끝나거나 재생이 실패하면 자동으로 결과창으로 넘어갑니다 — 어떤 경우에도
게임이 멈추지 않습니다.
