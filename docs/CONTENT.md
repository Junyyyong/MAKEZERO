# 로고

워드마크는 폰트가 아니라 **블록으로 그린 그림**입니다. `scripts/build-logo.mjs` 가 글자 비트맵에서 SVG를 만듭니다.

```bash
node scripts/build-logo.mjs > public/logo.svg
```

- 글자 모양은 스크립트 맨 위 `GLYPHS` / `SMALL` 의 `#` 격자입니다. 한 줄이 한 픽셀 행이에요
- 색은 `cool`(TAP) · `warm`(to) · `hot`(TEN) 그라데이션 세 개뿐이고, **`tokens.css` 의 팔레트와 같은 값**입니다. 한쪽을 바꾸면 다른 쪽도 바꿔야 합니다
- `CELL` 은 블록 한 칸, `DEPTH` 는 뒤로 밀린 판의 두께입니다

# 그림 (갤러리)

스테이지마다 그림이 한 장 있고, 판을 전부 지우면 그 그림을 얻습니다. 목록은 `src/content/gallery.ts` 의 `PLATES` 입니다.

```ts
{ stage: 1, title: "새싹 1", art: "./gallery/001.webp" }
```

- `art` 는 `public/` 아래 경로입니다. **비워 두면 스테이지 번호로 만든 임시 그림**이 대신 나옵니다
- 정사각형이 가장 잘 맞습니다. 판이 세로로 길어져도 `cover` 로 잘리며 채워집니다
- 그림은 판 **뒤**에 깔리고 지운 칸으로 보입니다. 그러니 **가장자리보다 가운데가 중요한 구도**가 좋습니다
- 갤러리 목록에서는 작은 정사각형으로, 눌러서 볼 때는 크게 나옵니다
- 판 위에서는 **블록 모양으로 나뉘어** 드러나고, 갤러리에는 나뉘지 않은 원본이 들어갑니다

### 그림이 나오는 자리 셋

같은 `art` 가 세 군데에 쓰입니다. 하나만 준비하면 됩니다.

- **게임판 뒤** — 블록을 지운 만큼, 블록 모양으로 나뉘어 드러납니다
- **스테이지 카드** — 스테이지를 고르면 뜨는 카드. 아직 못 얻은 스테이지는 `?` 만 보입니다
- **갤러리** — 나뉘지 않은 원본

### 99장을 한 번에 넣으려면

`public/gallery/001.webp` … `099.webp` 로 넣고 `PLATES` 의 `art` 를 채우면 됩니다. 파일명 규칙만 지키면 한 줄로 생성할 수 있습니다.

```ts
art: `./gallery/${String(stage).padStart(3, "0")}.webp`
```

# 캐릭터와 스토리 교체

## 대사

`src/content/chapters.ts` 의 `CHAPTERS` 배열만 고치면 됩니다.

```ts
{
  id: "sprout",                    // 저장용 식별자 — 바꾸면 그 챕터를 다시 봅니다
  title: "1장 · 첫 그루터기",
  character: "./story/sprout.svg", // public/ 아래 경로
  characterName: "새싹",
  lines: ["첫 번째 대사", "두 번째 대사"],
}
```

`lines` 에 넣은 만큼 한 줄씩 넘어갑니다. 개수 제한 없습니다.

## 이미지

`public/story/` 에 **같은 파일 이름으로 덮어쓰면** 코드는 건드릴 필요가 없습니다.

지금 들어있는 SVG 4개는 **자리를 잡아둔 임시 그림**이고, 11개 챕터가 그 4장을 돌려 씁니다. 챕터마다 다른 그림을 주려면 `public/story/` 에 파일을 추가하고 `chapters.ts` 의 `character` 경로만 바꾸면 됩니다. 조건은 이렇습니다.

- 형식: svg · png · webp · jpg
- 비율: 세로가 조금 긴 형태 (기준 128×160)
- 화면에서 148px 정도로 표시됩니다
- 배경은 투명하게 두면 카드 위에 자연스럽게 얹힙니다

다른 이름을 쓰고 싶으면 `chapters.ts` 의 `character` 경로도 같이 바꾸세요.

## 챕터 추가

`CHAPTERS` 에 항목을 추가하면 **스테이지 수도 같이 늘어납니다** (챕터당 9스테이지, 지금은 11챕터 99스테이지). 난이도 곡선은 전체 스테이지 수에 맞춰 자동으로 다시 펴집니다.

챕터당 스테이지 수를 바꾸려면 같은 파일의 `STAGES_PER_CHAPTER` 를 고칩니다.

## 스토리가 나오는 시점

챕터의 **마지막 스테이지를 별 1개 이상으로 통과**했을 때 한 번 재생됩니다. 이미 본 챕터는 `seenChapters` 에 기록되어 다시 나오지 않습니다.

테스트 중에 다시 보려면 브라우저 콘솔에서:

```js
localStorage.removeItem("makezero.progress.v1");
```

# 화면 흐름

```
타이틀 ─ 스토리 ──→ 챕터 목록 ─→ 스테이지 그리드 ─→ 스테이지 카드 ─→ 게임
       ├ 타임어택 ─→ 시작 화면 ────────────────────────────────→ 게임
       └ 무제한 ──→ 시작 화면 ────────────────────────────────→ 게임
```

- 모드를 눌러도 바로 시작하지 않습니다. 스토리는 어떤 그림이 걸려 있는지 보고 고르고, 시간 모드는 무엇을 재는지 먼저 보여줍니다
- 게임 안의 뒤로가기는 **들어온 길로** 나갑니다. 스토리는 스테이지 그리드로, 시간 모드는 타이틀로
- 결과 패널의 "다시 하기"는 고르는 화면을 거치지 않고 그 자리에서 다시 시작합니다
- 화면 사이 전환은 `AppStateMachine` 이 지킵니다. 허용되지 않은 이동은 예외로 막힙니다 (`src/ui/appStateMachine.ts`)

# 튜토리얼

`src/content/tutorial.ts` 의 `TUTORIAL_STEPS` 배열입니다. 다섯 단계로, **직접 눌러봐야 넘어갑니다.**

```ts
{
  id: "sum-ten",
  layout: [            // 0 은 빈 칸
    [4, 0, 6],
    [0, 3, 0],
    [2, 0, 0],
  ],
  instruction: "숫자를 눌러 합이 10을 만들면 지워집니다.\n4와 6을 눌러보세요.",
  reward: "그거예요! 합이 10이면 사라집니다.",
}
```

## 보드를 고칠 때 꼭 지킬 것

**보드마다 합이 10이 되는 조합이 정확히 하나만 있어야 합니다.**

그래야 게임의 진짜 규칙으로 정답을 판정할 수 있습니다. "이게 내가 의도한 수인가?"를 따로 검사하지 않으니, 튜토리얼이 규칙과 어긋날 일이 없습니다.

정답 외의 타일은 있어도 됩니다. 오히려 그게 교육 포인트입니다.
- `same-number` 단계의 3 두 개 — 짝처럼 보이지만 안 지워짐
- `anywhere` 단계의 4들 — 9와 1 사이가 멀다는 걸 보여줌

**레이아웃을 바꾸면 `npm test` 를 돌리세요.** `content/tutorial.test.ts` 가 정답이 두 개 이상 생겼는지 검사합니다.

## 언제 나오나

**처음 실행하면 자동으로** 나옵니다. 끝내거나 건너뛰면 다시 안 나오고, 타이틀 화면의 "튜토리얼"로 언제든 다시 볼 수 있습니다.

다시 테스트하려면 브라우저 콘솔에서:

```js
localStorage.removeItem("makezero.progress.v1");
```
