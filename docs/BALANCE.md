# 밸런스 조정

## 스토리 — 99 스테이지

**목표는 판을 전부 지우는 것입니다.** 모든 판은 반드시 전부 지울 수 있게 깔립니다(측정: 어느 스테이지·어느 시드에서도 100%). 그래서 막히는 건 운이 아니라 **실수**이고, 그래서 **되돌리기**가 있습니다.

`src/content/stages.ts` 상단 두 줄이 전부입니다.

```ts
const EASIEST = { rows: 4,  hints: 5, undos: 5, nearly: 0.16 };
const HARDEST = { rows: 11, hints: 0, undos: 1, nearly: 0.14 };
```

| 항목 | 뜻 |
| --- | --- |
| `rows` | 보드 줄 수. 가로는 9열 고정 |
| `hints` | 힌트 횟수 |
| `undos` | 한 수 물리기 횟수. **0이 되면 안 됩니다** — 막힌 판을 살릴 방법이 사라집니다 |
| `nearly` | 별 1개(위로상) 기준: 이만큼 이하로 남기면 통과 |

숫자 배분은 `groupWeights` 가 `EASY_GROUPS`(큰 조각) → `HARD_GROUPS`(짝 위주)로 흘러갑니다. **이게 진짜 난이도 다이얼입니다.**

### 별

| 별 | 조건 |
| --- | --- |
| ★★★ | 전부 지움 + **힌트·되돌리기 0회** |
| ★★ | 전부 지움 |
| ★ | `nearly` 칸 이하로 남김 (다음 스테이지는 열립니다) |
| 없음 | 그보다 많이 남김 |

별 1개를 관대하게 둔 이유는 하나입니다 — **진행이 막히면 안 되니까.** 도전은 ★★★이 맡습니다.

### 측정한 곡선

봇 40시드 기준입니다. "아무거나"는 가능한 수 중 무작위, "신중"은 **판을 계속 전부 지울 수 있게 유지하는 수만** 고르는 봇입니다.

```
스테이지  판     딜 가능  아무거나로 빈 판  평균 남음  신중  힌트/물리기  ★기준
   1     9x 4   100%        35%           3.6칸  100%    5/5        6칸
  10     9x 5   100%        33%           4.6칸  100%    5/5        7칸
  20     9x 5   100%        35%           3.2칸  100%    4/4        7칸
  30     9x 6   100%        18%           4.5칸  100%    4/4        8칸
  40     9x 7   100%        10%           4.8칸  100%    3/3       10칸
  50     9x 8   100%         8%           7.0칸  100%    3/3       11칸
  60     9x 8   100%         3%           8.0칸  100%    2/3       11칸
  70     9x 9   100%         3%          10.2칸  100%    1/2       12칸
  80     9x10   100%         0%          13.8칸  100%    1/2       13칸
  90     9x10   100%         0%          13.9칸  100%    0/1       13칸
  99     9x11   100%         0%          17.2칸  100%    0/1       14칸
```

읽는 법:

- **딜 가능 100%** — 어느 판이든 전부 지울 수 있습니다. 이건 변하지 않습니다
- **신중 100%** — 신중하게 두면 언제나 다 지웁니다. 난이도는 "가능한가"가 아니라 **"실수를 얼마나 용서하는가"** 입니다
- **아무거나 35% → 0%** — 초반엔 대충 둬도 종종 비워지고, 후반엔 절대 안 됩니다
- **★기준이 평균 남음보다 살짝 위** — 대충 둔 사람도 별 하나로 진행은 하되, 별 둘부터는 생각해야 합니다

### 왜 크기가 아니라 배분이 다이얼인가

큰 조각으로 깔면 작고 유연한 숫자가 남아서 대충 둬도 정리됩니다. 짝 위주로 깔면 8·9가 넓게 흩어지고, 9는 1하고만, 8은 2 아니면 1+1하고만 지워지므로 **한 수만 잘못 둬도 고아가 생깁니다.** 자세한 근거는 [DECISIONS 14번](./DECISIONS.md).

## 무제한 모드 (생존)

`src/content/stages.ts` 의 `ENDLESS_CONFIG.spawn` 입니다.

```ts
spawn: {
  initialFill: 0.45,      // 처음에 보드의 45%를 채움
  startIntervalMs: 3200,  // 첫 블록 간격
  minIntervalMs: 650,     // 아무리 빨라져도 이 아래로는 안 감
  rampMs: 55,             // 블록 하나 떨어질 때마다 이만큼씩 짧아짐
}
```

**`minIntervalMs` 가 이 모드의 전부입니다.** 사람이 실제로 칠 수 있는 속도보다 **살짝 아래**여야 합니다.

- 사람 속도보다 **위**로 두면(예: 850ms) 빠른 플레이어가 채워지는 속도를 추월해서 **영원히 안 죽습니다.** 실제로 15분을 버티고도 안 끝났습니다
- 너무 **아래**로 두면(예: 400ms) 바닥이 모두를 똑같이 죽여서 **실력 차이가 사라집니다.** 빠른 사람과 느린 사람의 생존 시간이 99초 대 62초로 붙어버렸습니다

650ms에서 측정한 생존 시간입니다. 봇이 N밀리초마다 한 번씩 지운다고 가정했습니다.

| 반응 속도 | 생존 | 점수 |
| --- | --- | --- |
| 1000ms | 178초 | 20,430 |
| 1400ms | 136초 | 8,460 |
| 2000ms | 115초 | 5,910 |
| 3000ms | 101초 | 3,780 |

빠를수록 오래 버티고 점수는 더 크게 벌어집니다. `content/pacing.test.ts` 가 이 관계를 검사합니다.
