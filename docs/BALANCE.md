# 밸런스 조정

## 어디를 만지나

`src/content/stages.ts` 상단 두 줄이 전부입니다.

```ts
const EASIEST = { width: 6, rows: 7, hints: 4, stars: [0.34, 0.18, 0.08] };
const HARDEST = { width: 8, rows: 9, hints: 1, stars: [0.24, 0.12, 0.03] };
```

1스테이지와 20스테이지 값만 정하면 **중간은 선형 보간**됩니다. 그래서 어떤 다이얼도 중간에 상한에 걸려 평평해지지 않습니다.

| 항목 | 뜻 |
| --- | --- |
| `width` / `rows` | 보드 크기. 화면에 꽉 차게 타일 크기가 자동 조절됩니다 |
| `hints` | 힌트 횟수 |
| `stars` | 남아도 되는 타일의 **비율** (별1 / 별2 / 별3) |

숫자 배분은 `src/core/board.ts` 의 `EASY_GROUPS` / `HARD_GROUPS` 입니다. **직관과 반대로 동작하니** [DECISIONS.md 4번](./DECISIONS.md)을 먼저 읽어주세요.

## 보드 크기와 화면 비율

타일은 정사각형이고 보드가 화면을 채우므로, 스토리는 첨부한 극장 레퍼런스와 같은 최대 8×9 구성까지만 커집니다.

| 보드 | 칸 수 | 아이폰에서 타일 크기 |
| --- | --- | --- |
| 6×7 | 42 | 큼 |
| 7×8 | 56 | 중간 |
| 8×9 | 72 | 작음 |

6×18 같은 세로로 긴 보드는 폭이 186px밖에 안 나와서 양옆이 텅 빕니다. `content/content.test.ts` 가 비율이 2를 넘으면 실패시킵니다.

## 바꾼 뒤 확인

```bash
npm test
```

`content/balance.test.ts` 가 20 스테이지의 보드 구성과 여러 시드를 검사합니다.

- 모든 스테이지가 첫 수를 제공하는가
- 보드가 42칸에서 72칸으로 커지는가
- 어려운 스테이지일수록 단단한 2개 조합 비율이 높아지는가
- 힌트와 별 허용 비율이 함께 줄어드는가

블록 수만 늘리면 선택지가 많아져 쉬워질 수 있습니다. 그래서 크기, 숫자 배분, 힌트, 별 기준을 반드시 함께 조정합니다.

## 무제한 모드 (생존)

`src/content/stages.ts` 의 `ENDLESS_CONFIG.spawn` 입니다.

```ts
spawn: {
  initialFill: 0.45,      // 처음에 보드의 45%를 채움
  startIntervalMs: 3200,  // 첫 블록 간격
  minIntervalMs: 650,     // 아무리 빨라져도 이 아래로는 안 감
  rampMs: 55,             // 블록 하나 떨어질 때마다 이만큼씩 짧아짐
}
```

**`minIntervalMs` 가 이 모드의 전부입니다.** 사람이 실제로 칠 수 있는 속도보다 **살짝 아래**여야 합니다.

- 사람 속도보다 **위**로 두면(예: 850ms) 빠른 플레이어가 채워지는 속도를 추월해서 **영원히 안 죽습니다.** 실제로 15분을 버티고도 안 끝났습니다
- 너무 **아래**로 두면(예: 400ms) 바닥이 모두를 똑같이 죽여서 **실력 차이가 사라집니다.** 빠른 사람과 느린 사람의 생존 시간이 99초 대 62초로 붙어버렸습니다

650ms에서 측정한 생존 시간입니다. 봇이 N밀리초마다 한 번씩 지운다고 가정했습니다.

| 반응 속도 | 생존 | 점수 |
| --- | --- | --- |
| 1000ms | 178초 | 20,430 |
| 1400ms | 136초 | 8,460 |
| 2000ms | 115초 | 5,910 |
| 3000ms | 101초 | 3,780 |

빠를수록 오래 버티고 점수는 더 크게 벌어집니다. `content/pacing.test.ts` 가 이 관계를 검사합니다.
