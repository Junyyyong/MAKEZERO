# 밸런스 조정

## 어디를 만지나

`src/content/stages.ts` 상단 두 줄이 전부입니다.

```ts
const EASIEST = { rows: 6,  hints: 5, stars: [0.42, 0.23, 0.075] };
const HARDEST = { rows: 11, hints: 1, stars: [0.2,  0.1,  0.028] };
```

1스테이지와 20스테이지 값만 정하면 **중간은 선형 보간**됩니다.

| 항목 | 뜻 |
| --- | --- |
| `rows` | 보드 줄 수. 가로는 9열 고정이고, 덱은 줄 수에 맞춰 1~9를 **줄 수만큼씩** 깝니다 |
| `hints` | 힌트 횟수 |
| `stars` | 남아도 되는 타일의 **비율** (별1 / 별2 / 별3) |

`stars` 는 비율로 적지만 화면에는 개수로 나옵니다. 보드가 커지면 같은 비율이 **더 큰 숫자**가 되어 스테이지가 쉬워 보이므로, `starTargetsFor()` 가 1스테이지부터의 **최솟값을 물려줍니다.** 목표는 절대 느슨해지지 않습니다.

**왜 크기가 난이도인지, 왜 숫자 배합은 건드리면 안 되는지**는 [DECISIONS 11번](./DECISIONS.md)에 측정치와 함께 있습니다. 요약하면 — 칸이 늘어도 최선의 결과는 그대로(0~1개)지만 대충 뒀을 때의 손해가 커지고, 반대로 덱을 큰 수 쪽으로 기울이면 **실력으로 어쩔 수 없는 죽은 타일**이 생깁니다.

## 현재 곡선

```
스테이지  1   6줄  54칸   ★23 ★★12 ★★★4   힌트 5
스테이지  5   7줄  63칸   ★22 ★★12 ★★★4   힌트 4
스테이지 10   8줄  72칸   ★22 ★★12 ★★★4   힌트 3
스테이지 15  10줄  90칸   ★22 ★★11 ★★★3   힌트 2
스테이지 20  11줄  99칸   ★20 ★★10 ★★★3   힌트 1
```

짝(2칸)만 맞추면 어느 스테이지든 0~1칸까지 내려갑니다. **별 3개는 언제나 가능하지만, 거의 완벽해야 합니다.**

## 보드 크기와 화면

타일은 정사각형이고 9열 고정이라 **가로가 타일 크기를 정합니다.** 세로는 남는 공간에서 알아서 맞춰집니다.

| 보드 | 칸 수 | 아이폰 15(393px)에서 타일 |
| --- | --- | --- |
| 9×6 | 54 | 34px |
| 9×9 | 81 | 34px |
| 9×11 | 99 | 34px |

가로가 같으니 타일 크기도 같고, 줄이 늘어난 만큼 세로로 길어집니다. 11줄이 세로로 안 들어가는 건 **가로 화면(844×390)뿐**이고, 안드로이드 빌드는 세로 고정입니다. 그래도 깨지지 않는지 `test:layout` 이 20스테이지까지 확인합니다.

## 바꾼 뒤 확인

```bash
npm test
```

`content/balance.test.ts` 가 봇으로 스테이지를 여러 시드씩 플레이해서 검사합니다.

- 짝을 맞추는 플레이는 어느 스테이지에서도 별 3개를 받는가
- 길게 잇는 플레이가 점수는 더 높은가, 그리고 보드가 커질수록 그 차이가 벌어지는가
- 길게 잇는 플레이는 별을 못 받는가 (둘이 서로 반대 방향인가)
- 목표가 스테이지가 올라가면서 느슨해지지는 않는가

봇은 **가장 긴 조합** 또는 **짝**만 집습니다. 사람은 그 사이 어딘가입니다.

## 무제한 모드 (생존)

`src/content/stages.ts` 의 `ENDLESS_CONFIG.spawn` 입니다.

```ts
spawn: {
  initialFill: 0.45,      // 처음에 보드의 45%를 채움
  startIntervalMs: 3200,  // 첫 블록 간격
  minIntervalMs: 650,     // 아무리 빨라져도 이 아래로는 안 감
  rampMs: 55,             // 블록 하나 떨어질 때마다 이만큼씩 짧아짐
}
```

**`minIntervalMs` 가 이 모드의 전부입니다.** 사람이 실제로 칠 수 있는 속도보다 **살짝 아래**여야 합니다.

- 사람 속도보다 **위**로 두면(예: 850ms) 빠른 플레이어가 채워지는 속도를 추월해서 **영원히 안 죽습니다.** 실제로 15분을 버티고도 안 끝났습니다
- 너무 **아래**로 두면(예: 400ms) 바닥이 모두를 똑같이 죽여서 **실력 차이가 사라집니다.** 빠른 사람과 느린 사람의 생존 시간이 99초 대 62초로 붙어버렸습니다

650ms에서 측정한 생존 시간입니다. 봇이 N밀리초마다 한 번씩 지운다고 가정했습니다.

| 반응 속도 | 생존 | 점수 |
| --- | --- | --- |
| 1000ms | 178초 | 20,430 |
| 1400ms | 136초 | 8,460 |
| 2000ms | 115초 | 5,910 |
| 3000ms | 101초 | 3,780 |

빠를수록 오래 버티고 점수는 더 크게 벌어집니다. `content/pacing.test.ts` 가 이 관계를 검사합니다.
