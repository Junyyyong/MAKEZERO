# 밸런스 조정

## 스토리 — 99 스테이지, 전부 9×9

**목표는 판을 전부 지워 뒤에 숨은 그림을 얻는 것입니다.** 모든 판은 반드시 전부 지울 수 있게 깔립니다(측정: 어느 스테이지·어느 시드에서도 100%). 그래서 막히는 건 운이 아니라 **실수**이고, 그래서 **되돌리기**가 있습니다.

**판 크기는 고정입니다 — 9열 9줄, 81칸.** 세 모드 전부 같습니다. `src/content/stages.ts` 상단 두 줄이 나머지 전부입니다.

```ts
const EASIEST = { hints: 5, undos: 8, splits: 3, nearly: 0.16 };
const HARDEST = { hints: 0, undos: 1, splits: 1, nearly: 0.14 };
```

| 항목 | 뜻 |
| --- | --- |
| `hints` | 힌트 횟수 |
| `undos` | 한 수 물리기. **0이 되면 안 됩니다** — 막힌 판을 살릴 방법이 사라집니다 |
| `splits` | 나누기 아이템 횟수 |
| `nearly` | 지금은 안 씁니다. 별을 없애면서 남은 값 |

### 보상

별 등급은 없습니다. **판을 전부 지우면 그 스테이지의 그림을 얻고**, 아니면 못 얻습니다.

### 측정한 곡선

봇 40시드 기준. "아무거나"는 가능한 수 중 무작위로 두는 최악의 플레이어, "신중"은 **판을 계속 전부 지울 수 있게 유지하는 수만** 고르는 봇입니다.

```
스테이지  딜 가능  아무거나로 빈 판  평균 남음  신중  1+2 비율  힌트/물리기/나누기
   1      100%        0%           6.6칸  100%    44%      5/8/3
  20      100%        0%           8.7칸  100%    41%      4/7/3
  40      100%        0%          12.3칸  100%    38%      3/5/2
  60      100%        0%          14.4칸  100%    34%      2/4/2
  80      100%        0%          16.6칸  100%    31%      1/2/1
  99      100%        0%          19.9칸  100%    27%      0/1/1
```

읽는 법:

- **딜 가능 100% · 신중 100%** — 어느 판이든 전부 지울 수 있고, 신중하게 두면 실제로 다 지웁니다. 이건 판 크기와 무관하게 지켜집니다
- **아무거나 0%** — 81칸에서는 아무 수나 두면 **절대** 못 비웁니다. 27칸이던 시절엔 절반쯤 비워졌습니다
- **평균 남음 6.6 → 19.9칸** — 초반엔 몇 칸만 어긋나고 후반엔 크게 어긋납니다. 실제 난이도 곡선은 여기 있습니다

**그래서 초반의 관대함은 되돌리기가 담당합니다.** 판을 줄여 쉽게 만드는 방법이 없어졌으니, 1스테이지에 **되돌리기 8회**를 줍니다. 6~7칸 어긋난 판은 몇 번 물리면 되돌아옵니다.

**숫자 배분으로 초반을 쉽게 만드는 안은 쓰지 않습니다.** 작은 수를 더 깔면 성공률은 오르지만 [DECISIONS 16번](./DECISIONS.md)에서 고친 1·2 쏠림이 그대로 돌아옵니다(1+2가 44% → 58%).

### 왜 크기가 아니라 배분이 다이얼인가

큰 조각으로 깔면 작고 유연한 숫자가 남아서 대충 둬도 정리됩니다. 짝 위주로 깔면 8·9가 넓게 흩어지고, 9는 1하고만, 8은 2 아니면 1+1하고만 지워지므로 **한 수만 잘못 둬도 고아가 생깁니다.** 자세한 근거는 [DECISIONS 14번](./DECISIONS.md).

## 무제한 모드 (생존)

`src/content/stages.ts` 의 `ENDLESS_CONFIG.spawn` 입니다.

```ts
spawn: {
  initialFill: 0.45,      // 처음에 보드의 45%를 채움
  startIntervalMs: 3200,  // 첫 블록 간격
  minIntervalMs: 650,     // 아무리 빨라져도 이 아래로는 안 감
  rampMs: 55,             // 블록 하나 떨어질 때마다 이만큼씩 짧아짐
}
```

**`minIntervalMs` 가 이 모드의 전부입니다.** 사람이 실제로 칠 수 있는 속도보다 **살짝 아래**여야 합니다.

- 사람 속도보다 **위**로 두면(예: 850ms) 빠른 플레이어가 채워지는 속도를 추월해서 **영원히 안 죽습니다.** 실제로 15분을 버티고도 안 끝났습니다
- 너무 **아래**로 두면(예: 400ms) 바닥이 모두를 똑같이 죽여서 **실력 차이가 사라집니다.** 빠른 사람과 느린 사람의 생존 시간이 99초 대 62초로 붙어버렸습니다

650ms에서 측정한 생존 시간입니다. 봇이 N밀리초마다 한 번씩 지운다고 가정했습니다.

| 반응 속도 | 생존 | 점수 |
| --- | --- | --- |
| 1000ms | 178초 | 20,430 |
| 1400ms | 136초 | 8,460 |
| 2000ms | 115초 | 5,910 |
| 3000ms | 101초 | 3,780 |

빠를수록 오래 버티고 점수는 더 크게 벌어집니다. `content/pacing.test.ts` 가 이 관계를 검사합니다.
