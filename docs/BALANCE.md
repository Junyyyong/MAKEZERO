# 밸런스 조정

## 어디를 만지나

`src/content/stages.ts` 상단 두 줄이 전부입니다.

```ts
const EASIEST = { width: 5,  rows: 8,  hints: 3, stars: [0.32, 0.18, 0.08] };
const HARDEST = { width: 10, rows: 15, hints: 1, stars: [0.26, 0.14, 0.05] };
```

1스테이지와 20스테이지 값만 정하면 **중간은 선형 보간**됩니다. 그래서 어떤 다이얼도 중간에 상한에 걸려 평평해지지 않습니다.

| 항목 | 뜻 |
| --- | --- |
| `width` / `rows` | 보드 크기. 화면에 꽉 차게 타일 크기가 자동 조절됩니다 |
| `hints` | 힌트 횟수 |
| `stars` | 남아도 되는 타일의 **비율** (별1 / 별2 / 별3) |

숫자 배분은 `src/core/board.ts` 의 `EASY_GROUPS` / `HARD_GROUPS` 입니다. **직관과 반대로 동작하니** [DECISIONS.md 4번](./DECISIONS.md)을 먼저 읽어주세요.

## 보드 크기와 화면 비율

타일은 정사각형이고 보드가 화면을 채우므로, **가로:세로가 대략 1 : 1.5**여야 화면이 꽉 찹니다.

| 보드 | 칸 수 | 아이폰에서 타일 크기 |
| --- | --- | --- |
| 5×8 | 40 | 69px |
| 6×9 | 54 | 61px |
| 7×11 | 77 | 52px |
| 8×12 | 96 | 45px |
| 9×14 | 126 | 40px |
| 10×15 | 150 | 33px |

6×18 같은 세로로 긴 보드는 폭이 186px밖에 안 나와서 양옆이 텅 빕니다. `content/content.test.ts` 가 비율이 2를 넘으면 실패시킵니다.

## 바꾼 뒤 확인

```bash
npm test
```

`content/balance.test.ts` 가 봇으로 20 스테이지를 12개 시드씩 플레이해서 검사합니다.

- 통과 못 할 스테이지가 없는가
- 1스테이지는 90% 이상 통과하는가
- 마지막 스테이지가 첫 스테이지보다 어려운가
- 별 3개가 너무 흔하지 않은가

봇은 **항상 가장 긴 조합**을 집습니다. 위치가 상관없어진 지금은 그게 거의 최적이라(짧은 조합 우선은 남은 타일이 3배), 이 점수는 **주의 깊은 플레이어의 하한선**으로 보시면 됩니다.
